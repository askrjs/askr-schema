# Schema API decisions for 0.5.0

Reviewed on 2026-10-09. Registry 0.4.1 declarations expose 21 names through the
TypeScript compiler API, including implementation declarations reachable from
the inferred builder object. The prepared root has seven deliberate names: one
runtime namespace and six types. A separate explicit barrel prevents private
declarations from becoming root exports. The manifest remains 0.4.1 pending
coordinated 0.5.0 qualification.

## Complete entrypoint and name inventory

| Export map key   | Decision | Reason                                                            |
| ---------------- | -------- | ----------------------------------------------------------------- |
| `.`              | KEEP     | Executable schema authoring, inference and integration contracts. |
| `./package.json` | KEEP     | Package identity/version inspection.                              |

No export-map key is removed. Implementation paths, including `schema` and
`dist/schema.js`, remain private and are rejected by packed consumer probes.

## Builder namespace review

All 23 members remain deliberate schema-authoring contracts. Their behavior is
exercised by a namespace-complete projection parity matrix and existing scalar,
format, modifier and object/combinator assertions.

| Member     | Decision | Supported contract                                                                            |
| ---------- | -------- | --------------------------------------------------------------------------------------------- |
| `string`   | KEEP     | String constraints, patterns and supported wire formats.                                      |
| `uuid`     | KEEP     | UUID wire schema used by core/server/examples and documented application authoring.           |
| `email`    | KEEP     | Email wire schema used by API examples.                                                       |
| `uri`      | KEEP     | Documented URI wire format with executable validation.                                        |
| `date`     | KEEP     | Documented calendar-date wire format with executable validation.                              |
| `dateTime` | KEEP     | Documented RFC 3339 wire format with executable validation.                                   |
| `byte`     | KEEP     | Documented base64 wire representation with executable validation.                             |
| `binary`   | KEEP     | Documented binary string wire metadata, distinct from base64 encoding.                        |
| `number`   | KEEP     | Finite numeric values and constraints.                                                        |
| `integer`  | KEEP     | Finite integral values and integer projection.                                                |
| `boolean`  | KEEP     | Boolean primitive validation/projection.                                                      |
| `null`     | KEEP     | Explicit null primitive validation/projection.                                                |
| `object`   | KEEP     | Object transport contracts, required/optional properties and explicit additional-key policy.  |
| `array`    | KEEP     | Element validation and size/uniqueness constraints.                                           |
| `record`   | KEEP     | Arbitrary own keys with one value schema.                                                     |
| `enum`     | KEEP     | A nonempty set of distinct finite primitive alternatives.                                     |
| `literal`  | KEEP     | One exact finite JSON primitive or null.                                                      |
| `optional` | KEEP     | Absent/undefined application property semantics.                                              |
| `nullable` | KEEP     | Explicit null values while preserving nested optionality.                                     |
| `oneOf`    | KEEP     | Exactly one matching member.                                                                  |
| `anyOf`    | KEEP     | At least one matching member.                                                                 |
| `allOf`    | KEEP     | Composed constraints and strict-object transport composition.                                 |
| `raw`      | KEEP     | Explicit caller-owned parser/projection seam for unsupported constructs and manual recursion. |

Format factories are intentional, documented wire vocabulary. They retain one
implementation through `schema.string`; no alternative parser is introduced.
There is no projection-only constructor or `parse()` method to preserve or add:
the executable contract is `safeParse()` plus `jsonSchema`.

## Migration for every removal

```ts
import { schema, type Schema, type InferSchema } from "@askrjs/schema";

type SafeParseResult<T> = ReturnType<Schema<T>["safeParse"]>;
type StringOptions = NonNullable<Parameters<typeof schema.string>[0]>;
type StringFormat = NonNullable<StringOptions["format"]>;
type NumberOptions = NonNullable<Parameters<typeof schema.number>[0]>;
type ArrayOptions = NonNullable<Parameters<typeof schema.array>[1]>;
type ObjectOptions = NonNullable<Parameters<typeof schema.object>[1]>;
type CommonOptions = NonNullable<Parameters<typeof schema.boolean>[0]>;

const object = schema.object({ name: schema.string() });
type ObjectValue = InferSchema<typeof object>;
const nullable = schema.nullable(schema.string());
type NullableSchema = typeof nullable;
const intersection = schema.allOf(
  schema.object({ name: schema.string() }),
  schema.object({ active: schema.boolean() }),
);
type IntersectionValue = InferSchema<typeof intersection>;
```

Replace root `array`, `object` and `string` imports with the corresponding
`schema` members. Replace `UnionToIntersection` with the inferred result of
the concrete composed schema. If application code needs optional key names,
derive them from its inferred value, rather than importing the schema builder's
property-map helper:

```ts
type OptionalKeys<T> = {
  [K in keyof T]-?: {} extends Pick<T, K> ? K : never;
}[keyof T];
```

Sibling source, examples, templates, package tests/docs and the original packed
declaration inventory were checked. None of the removed names has a named
sibling import in that inventory; the package's type fixture and raw-parser
documentation were migrated from `SafeParseResult` to the derived result.
Kept type imports identify real core/server/example integration needs, rather
than compatibility aliases.

The packed test verifies exact runtime and declaration exports, all fourteen
negative removed imports, required/optional inference and private subpath
rejection on Linux, Windows and macOS. The complete 0.5.0 candidate package set,
generated starters, examples and website API data still require coordinated
qualification; this patch alone does not close API issue #57.
